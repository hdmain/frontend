DOCUMENTATION GUIDES
SSH login: https://docs.alfahost.eu/guides/ssh/
  Default Linux SSH port 22 on KVM / classic VPS; NAT VPS uses the first port of the assigned block (not 22).
  Clients: ClientOSH (recommended), PuTTY, Termius, system OpenSSH.
  Keys: ssh-keygen ed25519, ssh-copy-id / authorized_keys.

  Same IP/user/password or key as SSH. ClientOSH folder icon, WinSCP, FileZilla, sftp/scp CLI.
First steps after SSH: https://docs.alfahost.eu/guides/first-steps/
  apt/dnf update, optional non-root sudo user, timedatectl Europe/Warsaw, ufw/firewalld without locking yourself out, prefer SSH keys, check df/free/htop.
RDP (Windows VPS): https://docs.alfahost.eu/guides/rdp/
  Default port 3389, user often Administrator. ClientOSH RDP, Windows mstsc, Microsoft Remote Desktop on macOS, Remmina/xfreerdp on Linux.
VPS NAT limits: https://docs.alfahost.eu/guides/nat-vps/
  Shared public IP; fixed port block (e.g. 20 ports); map 1:1; SSH on first port; hard CPU/RAM/disk caps; Mbps rate limit; monthly traffic (UTC); throttle ~8 kbit/s after traffic exhausted; unprivileged LXC (no nested Docker typically).


FAQ (PUBLIC)
Is anti-DDoS free?
Yes. Every plan includes multi-layer protection from day one, no activation fee and no paid add-on.

How fast can I deploy?
Most game images and VPS templates are ready within seconds after payment clears.

Where are the servers?
Game servers and NAT VPS run in Warsaw, Poland. KVM VPS is available in Frankfurt, Germany and in the Netherlands. Dedicated servers are in the EU.

NAT vs KVM?
NAT = shared host IP + dedicated 20-port block, Incus/LXC container, lowest price, Linux images only (Ubuntu/Debian).
KVM = own public IPv4, full virtual machine, Linux or Windows Server, higher isolation, DE or NL location.

VPS NAT
Category: vps
Location: Warsaw, Poland
Platform: Incus containers (LXC model — shared host kernel, hard resource isolation)
Summary: Affordable NAT VPS with 20 public ports for lightweight services and private projects.
Description: Compact virtual server with 20 public ports for small apps, test environments and services that do not need a dedicated public IPv4.
Ideal for: Small services, development environments and private projects.
Network: shared public IPv4 of the host; dedicated block of 20 public ports mapped 1:1 (example block 20040–20059).
SSH: OpenSSH on the first port of the block (example: ssh root@PUBLIC_IP -p 20040), not port 22.
If the guest enables ufw/firewalld, open the same SSH port as sshd uses (first of the block).
Anti-DDoS included.
Docs: https://docs.alfahost.eu/guides/nat-vps/
Offer page: https://alfahost.eu/en/offer/vps-nat/

Resource limits (hard caps):
CPU: whole cores or fractions (e.g. 0.5) enforced with CFS.
RAM: MiB hard limit; OOM kills when exceeded.
Disk: GiB rootfs; guest df shows only allocated space.
Bandwidth Mbps: instantaneous rate both directions.
Traffic monthly GiB: sum of download+upload per UTC calendar month; resets at month start; after exhaustion link throttled to ~8 kbit/s for residual admin access.
Isolation: unprivileged container; no access to other VPS or host SSH/API; nesting/privileged Docker usually disabled.
